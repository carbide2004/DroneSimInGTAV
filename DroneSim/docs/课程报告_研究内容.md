# 2 研究内容

## 2.1 数据平台总体框架

本平台以“游戏世界即数据发生器”的理念为核心，将 GTAV 的开放世界作为无人机视觉与控制研究的试验场。整体架构采用双层分离：
- 底层是内嵌于游戏进程的插件组件，负责与引擎的渲染与脚本线程安全互动、完成 RGB/Depth 的采集与环境控制；
- 上层是外部的 Python 客户端，承担实验编排、交互控制、数据记录与可视化。

两者通过轻量的二进制协议进行通信，实现了控制指令与数据的低延迟闭环。平台强调：
- 可扩展性：协议版本化与指令集合可演进；
- 鲁棒性：严格在脚本线程执行原生调用，避免跨线程副作用；
- 可复现性：采集路径内存直通、日志统一与结构化会话记录，便于对比与复现实验。

## 2.2 主脚本逻辑设计

脚本线程承担“调度者”的角色，以队列驱动的事件循环将来自客户端的抽象意图映射为游戏内的安全操作：
- 状态机：以“相机模式”为核心状态，收到创建指令再进入控制态，保证资源的生命周期与用户意图一致；
- 同步策略：采集触发与位姿填充均在游戏线程内完成，避免不确定性；
- 时序管理：为高频控制与采集提供细粒度延时与节流，使渲染稳定后再进行数据读取。

这种“以线程安全为前提的调度”使平台在复杂场景与长时间实验中保持一致性与可靠性。

## 2.3 无人机控制逻辑和场景编辑逻辑设计

控制逻辑以“研究友好”的连贯性为目标：
- 位移模型：以相机姿态为参照，将前向、侧向与世界竖直轴三分量合成，实现自然的自由度；
- 旋转模型：基于相机当前旋转的增量更新，支持精确航向调整；
- 光学参数：提供 FOV 设置以模拟不同镜头与任务需求。

场景编辑作为“可控环境”的设计维度：
- 时间控制：设置游戏时钟，以统一光照与影子条件；
- 天气控制：持久化切换天气类型，构造多样观测条件与对抗场景。

这些能力基于 GTAV 的原生 API（CAM、TIME、GAMEPLAY 等），在不破坏游戏机制的前提下开放必要的研究自由度。

## 2.4 RGBD 数据采集流程设计

采集流程设计遵循“尽可能接近引擎”的原则：
- 触发窗口：在渲染管线的关键节点进行颜色与深度缓冲读取，避免二次渲染与重构成本；
- 数据直通：将 RGB 与深度以内存形式直接返回客户端，降低 I/O 干扰，方便即时处理与可视化；
- 质量控制：对深度采用稳健的可视化策略（分位数裁剪）以抵御极端值影响；
- 多视角策略：支持围绕当前姿态的多方向采集（正前、后、左、右、下），为全景感知与数据集构建提供结构化支持。

这一流程兼顾了实时性与可用性，适合用于机载感知、环境对比与数据驱动建模等研究任务。

## 2.5 通信协议设计

协议采用紧凑的二进制结构，以低开销与清晰语义为目标：
- 统一消息头：包含魔术字、版本、类型与长度等字段，保障解析与扩展；
- 指令集合：覆盖创建相机、位移与旋转、FOV、采集、位姿、时间与天气控制等核心能力；
- 可靠交互：请求标识与短连接通信的组合，简化异常路径与恢复逻辑。

这种“语义清晰 + 约束简洁”的设计，使得协议既能承载当前需求，又可自然生长至更复杂的实验编排。

## 2.6 客户端 SDK 设计

SDK 以“研究者友好”的交互体验为出发点：
- 统一 API：提供创建、控制、采集与环境设置的直观方法，降低学习门槛；
- 稳定性考量：在每次操作后引入轻量的时延，使渲染稳态后再读取数据，提升交互一致性；
- 采集编排：支持以键盘或脚本驱动的会话记录，将每一帧的多方向 RGBD 与动作元信息结构化保存，利于后续分析与复现。

在此基础上，SDK还为可视化与数据落盘提供便捷工具，形成“从控制到观测到记录”的完整闭环，服务于感知、控制与环境建模等跨领域研究。

---

总体而言，平台通过“线程安全的脚本调度 + 低开销的协议通信 + 面向研究的采集与控制”实现了在虚拟世界中的数据与控制的一体化。它不仅支持快速实验搭建，更为学术研究提供了可复现、可扩展与可对比的坚实支撑。
